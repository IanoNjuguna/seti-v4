# Elevation Protocol

A systematic process for moving from functional first draft to polished final output. Run this internally. Deliver only the final result unless the user asks to see the process.

## Stage 0: Understand

Before designing, answer:
- What is this artifact for?
- Who will use it and in what context?
- What is the single most important message?
- What action should the user take?

Do not start visual work until these are clear.

## Stage 1: Structure

Create the functional version first.

- Lay out the content in a clear reading order.
- Group related information.
- Establish a rough type scale.
- Place the primary CTA or focal point.

This stage should solve the problem. It does not need to be beautiful.

## Stage 2: Interrogate

Apply the design-interrogation-checklist.md. Ask:
- Is the hierarchy obvious?
- Is anything unnecessary?
- Are defaults doing work that should be intentional?
- Does the layout match the mood of the content?

Make notes but do not refine yet.

## Stage 3: Direct

Choose a design direction from the reference-library.md. Pick one primary reference and one secondary reference. Decide:
- Theme paradigm (light, dark, neutral, bold)
- Typography character
- Composition anchor
- Color logic

Do not mix unrelated moods.

## Stage 4: Apply techniques

From technique-catalog.md, select 2–4 specific techniques that serve the artifact’s goal. Write them down. Apply them consistently.

Examples:
- "Use scale contrast + tight tracking for headlines"
- "Use generous margins + flat surfaces for calm"
- "Use asymmetric composition + bold accent block for energy"

## Stage 5: Refine

Polish the details:
- Align everything to a consistent grid
- Normalize spacing (use an 8pt or 4pt base)
- Audit color usage
- Check contrast
- Tighten copy
- Ensure consistency in radius, borders, and shadows

## Stage 6: Review

Step back and ask:
- Does this look like one coherent system?
- Would I be proud to show this to a design director?
- Is the most important thing the most visible thing?
- Is anything generic or template-like?

If yes, deliver. If no, return to Stage 3 or 4.

## Stage 7: Deliver

Present the polished artifact. Include only what the user needs to see. If asked, explain the design decisions concisely.
