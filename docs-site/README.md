# Seti docs site

Docusaurus site that publishes the product docs in [`../docs`](../docs). There is
**one copy of the docs**: this site renders `docs/*.md` directly (`docs.path:
'../docs'`), so editing a page in `docs/` changes the published site and the two
cannot drift.

## Run it

```bash
cd docs-site
npm install        # standalone — see below
npm run start      # dev server, hot reload
npm run build      # static output in build/
npm run serve      # serve the built output locally
```

## Why this is standalone and not an npm workspace

`docs-site/` is deliberately **not** a member of the root `workspaces` array in
`package.json`. The repo runs on a single root lockfile and `npm run verify`
covers exactly `backend`, `mobile` and `web`; adding a fourth workspace would
pull this site's build toolchain into the repo's install and lockfile, and a
docs-site dependency conflict could then break the app's gate. Keeping it
separate means:

- `npm install` at the repo root is unaffected;
- `npm run verify` still covers only the three app packages;
- this site has its own `package-lock.json`, which is the point — it pins its own
  dependency tree and cannot destabilise the app's.

The repo's "install from the root only" rule applies to the three workspace
packages. This is a separate package with its own lockfile, which is why its
`node_modules` and `build/` are gitignored here.

## Content and configuration

| File | Role |
| --- | --- |
| `docusaurus.config.ts` | Site metadata, and the `classic` preset with `docs.path: '../docs'`, `routeBasePath: '/'` |
| `sidebars.ts` | Autogenerated from `../docs`, so adding or renaming a page never requires editing an ID |
| `src/css/custom.css` | Infima theme colours, using the same brand primary as `web/app/globals.css` |
| `static/img/favicon.png` | The phoenix mark, padded to a square (not stretched) |

`docs/SUMMARY.md` is excluded from the build — it is GitBook's navigation file and
would otherwise render as a stray page. `gitbook-docs.yaml` and `docs/.gitbook.yaml`
are kept so the same content can be imported into GitBook later without a rewrite.

## Verifying a change

`npm run build` is the gate, and it is stricter than it looks: `onBrokenLinks` and
`onBrokenMarkdownLinks` are both `throw`, so a link to a page that does not exist
fails the build rather than shipping a dead link. Run `npm run typecheck` after
touching the config.
